# 流程图规则

流程图回答：**业务下一步怎么走？**

## 必须表达的路径（核心流程涉及时）

- 成功路径与失败路径
- 条件分支
- 重试（含次数上限与退避）
- 超时
- 回滚
- 重复请求/幂等检查
- 权限失败

## 判断节点与分支

判断节点使用明确问题，分支必须标记结果：

```text
{用户是否登录？} → 是 / 否
{库存是否充足？} → 是 / 否
{请求是否成功？} → 成功 / 失败
```

## Mermaid flowchart 语法要点

- 判断节点用 `{}`，起止节点用 `([ ])`，普通节点用 `[ ]`
- 分支标签写在边的竖线中：`CHECK -->|是| NEXT`
- 节点文本含括号、引号等特殊字符时必须加引号：`A["文本(含括号)"]`
- 避免用 `end` 作为节点 ID（与块关键字冲突），用 `DONE` 或 `FINISH`
- 布局方向：线性流程用 `TD`，宽流程用 `LR`
- 重试回路：失败判断 → 退避等待 → 指回主流程
- 回滚路径：事务中段 → 回滚节点 → 失败处理
