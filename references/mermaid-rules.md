# Mermaid 规则

Mermaid 是标准图表源文件。保持可读、命名统一、箭头方向正确。避免无意义样式和过度复杂的图。

## 高频语法陷阱清单

生成和同步后逐条自检：

1. 节点文本含括号、方括号、引号等特殊字符 → 必须整体加引号：`A["登录(微信)"]`；错误写法：`A[登录(微信)]`
2. 分支必须带标签（是/否、成功/失败），写在边标签中
3. subgraph 标题含空格 → 用 `subgraph FE[Front End]` 形式
4. 节点 ID 全图唯一，每个节点只定义一次文本
5. 时序图：请求用 `->>`，响应用 `-->>`；flowchart 的 `-->` 不能用于时序图
6. 避免用 `end` 作为节点 ID（与块关键字冲突），改用 `DONE`、`FINISH`
7. 节点文本中避免全角空格等不可见字符
8. `alt`/`loop`/`opt`/`par` 片段必须有配对的 `end`
9. flowchart 与 sequenceDiagram 不能混在同一源文件
10. `%%` 开头为行注释，可用于标注图的业务域

## 渲染验证

生成或大幅修改 .mmd 后，环境允许时用 mermaid-cli 验证：

```bash
npx -y @mermaid-js/mermaid-cli -i diagram.mmd -o /tmp/diagram.svg
```

渲染失败按报错行号修复。无法执行时，至少完成上述清单逐条自检。

## 同步前检查

1. 节点、参与者名称唯一且使用项目真实名称
2. 箭头方向与真实调用方向一致
3. 分支都有标签
4. 已删除的组件在图中同步移除，不留孤儿节点和悬空边
